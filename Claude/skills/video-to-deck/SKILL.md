# 影片 → 字幕文字檔 + 教學簡報 + 逐頁講稿

把一部講解型影片變成三樣東西，三者互相對得上時間：

1. **字幕文字檔**：每句帶 `[mm:ss]` 時間戳（原文一份；使用者的語言不同時再轉一份）。
2. **簡報 .pptx**：照影片的講解順序，每頁把「問題 → 原因 → 解法」講完整，備忘稿裡有講稿。
3. **逐頁講稿 .txt**：每頁的對應影片時間＋可直接照念的講稿。

除非使用者另有指定，三樣都做，語言跟使用者的訊息一致（例如使用者用繁體中文、影片是簡體，簡報與講稿就用繁體與台灣用語）。成品放在工作資料夾（session 的資料夾），中間檔放 scratchpad。

腳本都在這個 skill 的 `scripts/`，下文以 `$SKILL` 代表 skill 資料夾。

## 0. 準備

- 需要 `ffmpeg`/`ffprobe`、Python（含 Pillow）、Node。缺 Pillow、OpenCC 等套件時，在 scratchpad 建 venv 再裝，不要動使用者的全域環境。
- 在 scratchpad 開一個工作資料夾（例如 `work/`）放 `node_modules`、build 腳本；影片抽出的圖放另一個資料夾（例如 `frames/`）。影片是外來檔案：不要在它的資料夾裡執行直譯器，Python 一律加 `-I`，路徑用參數傳。
- 做簡報前先載入 `pptx` skill（設計規範、驗證、QA 的要求都以它為準）。這個 skill 只補上「影片 → 內容」以及這類簡報的現成零件。

## 1. 探測：影片有沒有燒錄字幕？

```bash
python -I "$SKILL/scripts/video_sheets.py" probe "VIDEO.mp4" "$SP/frames"
```

讀它產生的 `probe.jpg`（6 張帶時間與高度刻度的畫面）。判斷兩件事：

- **畫面上有沒有字幕**，以及字幕落在畫面高度的哪一段（刻度 .1–.9 是高度比例）。常見是 0.82–0.95。
- 影片大概是什麼類型（動畫講解、投影片錄影、真人講話），這決定之後要多看圖還是多看字。

## 2. 取得逐字內容

**有燒錄字幕（優先，最準、免下載模型）：**

```bash
python -I "$SKILL/scripts/video_sheets.py" extract "VIDEO.mp4" "$SP/frames" --band 0.82,0.95
```

它會把字幕帶裁出來、去掉連續重複、疊成一張張「字幕長條圖」（`sheets/sub_NN.jpg`，每張 36 句、左邊是時間），另外把關鍵畫面排成 4×4 的縮圖（`sheets/full_NN.jpg`）。

- **每一張 `sub_*.jpg` 都要讀**，這是內容的唯一來源，不能跳著看或憑印象補。10 分鐘的影片大約 12 張。
- `full_*.jpg` 挑著看：看影片用了哪些圖解（表格、樹、架構圖、流程），之後在簡報裡重畫同樣的概念；也留意畫面上字幕沒唸出來的文字（備註、圖上的標籤）。
- 字幕帶裁錯（字被切到、裁到別的東西）就調 `--band` 重跑；字幕換得很快可調 `--sub-fps 3`。

**沒有燒錄字幕：** 先 `extract --no-subs` 取關鍵畫面，再用語音轉文字。這要下載模型（`small` 約 460 MB），先跟使用者說一聲再做：

```bash
python "$SKILL/scripts/transcribe.py" "VIDEO.mp4" "$SP/work/transcript_raw.txt" --model small --lang zh
```

語音辨識的專有名詞常錯，對照關鍵畫面上的文字修正。

## 3. 寫字幕文字檔

格式（照影片的章節分段，章節標題用影片裡的轉場畫面）：

```
影片字幕（原文，與畫面字幕一致）
影片：<片名>（<來源>）
時長：約 mm:ss
說明：時間戳為該句首次出現的時間（誤差約 ±0.5 秒），連續重複的字幕已合併。

# <章節>
[00:52] 什么是Elastic Search
[00:53] Elastic Search也就是ES
```

- 忠於原文。字幕本身的錯字（自動辨識常見，如 Hash 寫成 Harsh、專有名詞被聽成別的字）**保留原樣，在該行後面用【注：應為…】標出**，不要默默改掉——使用者要的是「影片上的字幕」，但也需要知道哪裡是錯的。
- 使用者的語言與字幕不同（簡↔繁）時，再轉一份：`python "$SKILL/scripts/convert_chinese.py" 原文.txt 繁體.txt --config s2twp`（需 `opencc-python-reimplemented`）。轉完檢查它列出的殘留字。

## 4. 規劃簡報內容（最重要的一步）

**原則：影片解釋過的原因，簡報都要有。** 這類簡報是拿來學習、拿來講的，不是給主管看的摘要。只寫結論（「Term Index 用於加速搜尋」）而丟掉推論（為什麼原本慢、為什麼這個結構小到能放記憶體）的簡報，使用者會覺得「過於簡潔」而退回來。

做法：

- 沿著字幕一段一段走，把每個概念寫成因果鏈：**遇到什麼問題 → 為什麼會這樣 → 怎麼解 → 得到什麼**。影片裡每個「因為／所以／但是／那怎麼辦」都應該落在某一頁上。
- **寧可拆頁，不要刪原因。** 一個概念若有「為什麼需要它」和「它怎麼運作」兩段，就做兩頁。密集的講解型影片大約每分鐘 2 頁（10 分鐘 ≈ 20–25 頁）。
- 每頁仍只講一件事，標題直接說出這件事（例如「為什麼 Term Dictionary 放不進記憶體？」）。
- 保留影片的具體例子（它用的句子、數字、類比），不要換成自己的例子；影片沒講的知識不要加，真的需要補充時標明是補充。
- 自己推論出來、影片沒明說的內容（例如把「更輕量」寫成具體缺點），交付時要告訴使用者。
- 使用者的說法和影片不一致時（例如把兩個名詞講反），在回覆裡點出來，並在簡報上把那一點講清楚。

結構：封面 → 問題起點 → 導覽頁（分幾部分＋閱讀方式）→ 各部分內容 → 全景／流程 → 重點回顧。

寫完大綱後做一次**覆蓋檢查**：從頭掃一遍字幕檔，確認每個章節、每個因果轉折都有對應的頁；找不到的就補頁。

## 5. 建立簡報與講稿

先在工作資料夾裝套件：`npm init -y && npm install pptxgenjs`。把 `$SKILL/scripts/example_build.js` 複製成 `build.js` 當起點（它可以直接跑，示範了下面每一點）。

**單一來源：** 用一個 `SCRIPT` 物件存每頁的 `title`、`time`（對應影片時間，如 `"02:04–02:15"`）、`script`（講稿）。投影片標題、備忘稿、講稿 .txt 全部由它產生，三者就不會對不上。講稿用口語寫、忠於影片、每頁約 100–300 字，可直接照念；`time` 從字幕檔的時間戳抄。

**零件：** `deck_kit.js` 的 `createDeck()` 提供三種版型（深色封面、淺色內容、深色結尾）與繪圖函式：

| 函式 | 用途 |
|---|---|
| `chain(slide, [[文字, 調性], …], x, y, w)` | 因果鏈，這類簡報的主力。調性：`p` 問題（粉）、`n` 中性、`s` 解法（淺綠）、`r` 結論（深色） |
| `chip` / `box` / `badge` / `callout` | 圓角標籤、卡片、編號圓點、底部重點條 |
| `line` / `flowArrow` / `downArrow` | 任意方向的連線與箭頭 |
| `bullets` / `text` | 條列與一般文字 |
| `titleSlide` / `content` / `closing` | 新增一頁（自動處理 section 與備忘稿） |
| `kit.save(out)` | 寫檔，並把配色與中日韓字型寫進佈景主題 |
| `writeScriptTxt(out, entries, header)` | 產生逐頁講稿 .txt |

版面習慣：內容區是 x 0.6–12.73、y 1.85–6.75 吋。典型的一頁是**左邊因果鏈（寬約 6 吋）＋右邊一張圖**，圖把同一件事畫出來：前後對照（之前／之後各一個面板）、流程、表格、樹、巢狀方塊。影片用過的圖解優先重畫。每頁都要有圖，不要純文字。在導覽頁說明顏色的意思。

配色依主題另選（改 `createDeck({ theme })`），不要每份都用預設的青綠色。字型：繁體用 Microsoft JhengHei，簡體用 Microsoft YaHei。

## 6. 檢查（必做）

1. **結構驗證**：跑 pptx skill 的 `validate.py`。
2. **逐頁轉圖看**：有 LibreOffice 就照 pptx skill 的方式；Windows 上沒有的話，用已安裝的 PowerPoint：
   ```bash
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(cygpath -w "$SKILL/scripts/render_pptx.ps1")" -Deck "$(cygpath -w deck.pptx)" -OutDir "$(cygpath -w "$SP/render")"
   ```
   每一頁都要看圖，不是只看程式碼。這類簡報最常見的問題：文字溢出方塊、**一兩個字掉到下一行**（中文的孤字、被拆開的英文詞組如 `index / name`）、因果鏈方塊高度估錯（傳第三個參數指定行數）、標籤文字沒置中。修完只重轉改過的頁（`-Only "7,12"`）。
3. **內容**：用 pptx skill 的 `slide_text.py` 確認每頁文字與備忘稿都在；講稿 .txt 的頁數要等於投影片數。

## 7. 交付

回覆裡說明：產出了哪些檔案、簡報的結構、你做了哪些判斷（哪些是自己的推論、哪裡和使用者的說法不同、字幕裡標了哪些錯字）、怎麼檢查的、有什麼沒檢查到。使用者之後要改內容時，改 `build.js` 重建並覆蓋同一個檔名，講稿與備忘稿會一起更新。

## 已知的坑

- **pptxgenjs 的 margin 陣列順序是 [左, 右, 下, 上]**，不是 CSS 的順序；用單一數字最安全（`deck_kit` 已如此）。
- **標題預設會置中**：版型的 placeholder 要明寫 `align: "left"`（`deck_kit` 已處理）。
- **中文字型**：pptxgenjs 的佈景主題沒填東亞字型，中文會變成新細明體；`kit.save()` 會補上。
- **Windows 路徑過長**：pptx skill 的 `validate.py` 在很深的資料夾裡會因為超過 260 字元而報一堆假的 schema 錯誤。把 pptx skill 的 `scripts/` 複製到 scratchpad 的短路徑再跑。
- **Windows 主控台編碼**：Python 輸出導到檔案或管線時是 cp950，用 `grep` 找中文會找不到。要驗證中文內容，在 Python 裡讀檔比對，或設 `PYTHONIOENCODING=utf-8`。
- **檔案被 PowerPoint 開著**時無法覆寫；請使用者先關掉。
- `render_pptx.ps1` 遇到損壞的檔案會卡在修復對話框，所以一定先驗證再轉圖。
